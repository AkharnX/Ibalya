# Volet 90 jours (retour BS ACCESS) : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Trois listes « je dois / on me doit / pour information », un engagement par promesse dans un fil, des interlocuteurs typés sans saisie, des dépendances rares et crédibles, et une synthèse qui s'ouvre sur trois décisions.

**Architecture:** Fonctions pures dans `engine` (sens, proximité d'objets, typage, enjeu), branchées dans `Suivi`, `createEngagement`, `RunGraphHeuristics` et `GenerateSynthese`. Deux routes nouvelles (typage automatique, rejet des candidats), un champ `sens` et un champ `enjeu` dans les réponses existantes. Pas de migration.

**Tech Stack:** Go (tests `go test`, sans base), React + Vite, pile jetable pour l'intégration.

**Spec:** `docs/superpowers/specs/2026-11-12-retour-bs-access-90-jours.md`

## Global Constraints

- Copie française sans tiret cadratin ni capitales espacées ; pas de chiffres inventés.
- Chaque tâche : `cd backend && go vet ./... && go test ./...` vert, `npm run lint && npm run build` vert si le frontend bouge, puis commit.
- Messageries grand public (liste de la spec) : jamais typées « interne » ni par domaine.

## Review Focus

1. Un engagement où le dirigeant est en copie entre deux tiers ne doit produire ni retard ni « C'est fait ? » (tâche 1 : test `Sens` → `pour_info`, et les détecteurs filtrent).
2. Deux engagements du même fil aux objets voisins mais de types incompatibles (devis et rendez-vous) restent deux engagements (tâche 2).
3. Un interlocuteur `@gmail.com` ne devient jamais « interne », même si le compte raccordé est aussi `@gmail.com` (tâche 3).
4. « Appliquer au domaine » sur une adresse `@orange.fr` ne doit toucher qu'elle (tâche 3).
5. Avec moins de trois priorités, la synthèse n'affiche ni cadre vide ni « Voir les 0 autres » (tâche 5).
